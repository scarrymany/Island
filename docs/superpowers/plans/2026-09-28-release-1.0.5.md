# SCARP ISLAND 1.0.5

## Goal

Polish the settings client and ship a verified Windows release. Preserve user profiles, HUD behavior and existing installation paths. Tests use temporary configuration and controlled media data; the user's playback and startup registration stay outside automated UI fixtures.

## Deliverables

1. Replace the editable update repository with a GitHub icon button opening the public project. Pin update requests to the official repository and normalize legacy configuration during loading and import.
2. Give the hotkey editor consistent inner spacing at supported font sizes and window sizes. Preserve recording, keyboard navigation and restore behavior.
3. Replace native choice and font popups with a shared styled presentation: bounded placement, consistent typography, rounded surfaces, animated opening and closing, keyboard selection and cancellation. Mouse focus must not leave an unintended outline. Reduced motion and monitor refresh settings must apply.
4. Exercise every settings group and action with temporary data, including profile/theme dialogs, import/export, error states, reset controls, source changes, page transitions and window lifecycle. Fix concrete failures discovered by this audit.
5. Check the deployed application without the development SDK and validate install/uninstall in the clean Windows CI environment. Publish 1.0.5 only after local checks, visual inspection and release CI pass.

## Ownership and interfaces

- Root: SettingsWindow, hotkey spacing, project button, release integration and visual acceptance.
- Dropdown worker: SettingsControls and popup implementation, with `setMotion(bool, int, double)` on both choice classes.
- Workflow worker: isolated workflow tests, visual acceptance harness and control coverage report.
- Update worker: AppInfo constants, UpdateService, ConfigStore and Application update behavior.
- `AppInfo::Repository` and `AppInfo::ProjectUrl` are the official public update identity. Existing configuration can contain the legacy field, but it cannot redirect official update requests.
- Only one worker builds the shared native build directory at a time.

## Acceptance evidence

- Regression tests demonstrate the reported padding, popup, font and focus defects before their fixes where reproducible.
- All normal CTest suites pass, including the settings workflow inventory.
- Native Windows screenshots verify popup placement, clipping, row typography, hotkey spacing, focus states and small-window behavior.
- Actual mouse and keyboard interaction exercises open, select, cancel, rapid reopen, outside click, page changes and window hide during transitions.
- Full release CI passes with deployment and installer checks. Uploaded installer and archive digests match SHA256SUMS.
- Release notes and the QA report distinguish verified scenarios from environmental limitations. They contain no references to private projects.
